## 가짜 OCR 자동 검증

기본 pytest는 OCR 어댑터를 주입한다. 형식·손상·바이트·화소·애니메이션 검증, EXIF 회전/제거, 빈 추출/실패/미설치/시간 초과 구분, 동시 요청 차단·취소 후 슬롯 복구, 자식 프로세스 kill/reap와 파일 미생성, 확인 누락/false/숫자/문자열 거부, 수정한 텍스트의 근거 좌표, URL 후보 초과 시 전체 텍스트 보존을 확인한다. 이는 실제 이미지 인식 테스트가 아니다. 기본 실행에서 실제 OCR 테스트 2개는 명시적으로 skip이다.

Vitest는 OCR 중복 제출·25초 대기·취소 뒤 늦은 응답 무시·이전 URL 후보 응답 무시·오류 코드별 고정 안내와 응답 계약을 검사한다. Playwright의 OCR 실패/빈 추출/시간 초과는 서버 응답을 가짜로 만들어 재현한다. 실제 시간 초과 재현은 백엔드 가짜 느린 어댑터의 취소 테스트와 구분한다.

## 실제 한국어 인식 검증

`RUN_REAL_OCR=1 ../.venv/bin/python -m pytest -q tests/test_ocr_real.py`는 가짜 어댑터 없이 실제 Tesseract를 실행한다. 고정 합성 한국어 PNG와 그 이미지의 JPEG 변환본 2개에서 한국어 요구 문장 및 URL을 확인했다. 빈 작업 디렉터리에서 실행 후 파일이 생기지 않는 것도 확인한다.

PNG 한 번의 관찰 출력은 아래와 같았다. 누락/철자 보정 없이 Tesseract 출력의 줄바꿈을 유지했다.

```text
은행 담당자입니다.

인증번호를 알려주세요.
https://example.invalid/notice
지금 바로 확인해주세요.
```

그 한 번의 엔진 실행은 약 0.25초였다. 전체 업로드/분석 지연·p50/p95·10초 제품 목표 달성이나 일반적인 OCR 정확도를 의미하지 않는다. 실제 사진, 잘림, 저해상도, 다른 글꼴, 회전, 복잡한 메신저 화면의 품질은 별도 대표 데이터 평가가 필요하다. 현재 rules-dev-v2는 순수 명의 도입과 인접 직접 요구에만 빈 줄을 넘는 신호 결합을 허용한다. 원문 문장을 합치지는 않으며 상세한 예외/한계는 [RULE_POLICY.md](RULE_POLICY.md)에 있다.

실제 Chromium 브라우저 검증에서는 이 PNG를 선택 → Blob 미리보기 → 실제 FastAPI/Tesseract OCR → 추출 한국어와 URL 확인 → 문자·URL 직접 수정 → 확인 체크 → 기존 Analyzer로 분석을 수행했다. 업로드/OCR/편집만으로 분석 API가 호출되지 않는지, 수정 시 체크와 이전 결과가 해제되는지, 수정한 URL이 조회 없이 표시되는지, 모바일 가로 넘침이 없는지 확인한다. 스크린샷은 Git에서 제외한 `frontend/test-results/ocr-review.png`다.

언어 데이터 설치 스크립트는 별도의 빈 임시 디렉터리에서도 실제 HTTPS 다운로드·SHA-256 검사·kor/eng 확인을 실행했고 디렉터리를 정리했다. 실행 중 데이터 다운로드는 없다. 테스트 이미지 원문은 개인정보가 없는 합성 예시이며 사용자 업로드 보관과 구분한다.

## Windows 사용자 확인 후 추가한 회귀 검증

사용자는 Windows에서 OCR 실행과 수정 후 분석까지 확인했다고 보고했다. 준비 스크립트의 `tesseract v5.5.3.20260724` 거부는 두 접두사 허용으로 수정했고, 실제 다운로드 없이 Windows/Linux 출력과 미지원 버전을 주입해 검증한다. 런타임에는 접두사 버전 검사가 없다. 이 보고와 Linux에서 직접 실행한 결과를 구분한다.

문단 판정은 한 줄/단일 개행/빈 줄/LF/CRLF에 대한 사용자 재현 사례와 화자 라벨·메신저 헤더·구분선·인용·교육·부정·일반 문단의 비결합 사례를 추가했다. 입력을 합치지 않고 근거 좌표를 보존한다.

OCR 편집 테스트는 이전 분석이 실제로 표시된 상태에서 문자/URL을 바꾼 **같은 이벤트 직후** 확인 해제·버튼 비활성·이전 결과 제거를 검사한다. Vitest는 await/waitFor 없이 검사하고, 실제 브라우저는 새 URL 후보 API 응답을 보류한 상태에서도 해제되는지 확인한다. `frontend/test-results/ocr-edit-reset.png`는 그 수정 직후 화면이다. 원래 이벤트 처리에는 이미 동기 해제가 구현되어 있어 제품 코드를 바꾸지 않고 이를 회귀 테스트로 고정했다.

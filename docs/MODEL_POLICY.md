> **임시, 팀 확정 필요.** 모델 신호의 반영 방식, 임계값 기준, 학습 라벨 매핑은 중간점검 시연을 위한 개발용 정책이다. PRD가 확정한 판정 경계·정확도·신뢰도·임계값이 아니다 (AGENTS.md "결정 필요" 1~3).

## 범위

- 모델: TF-IDF 문자 n-gram(`char_wb`, 2~4) + 로지스틱 회귀 하나. 중간점검의 기준선이다. KoELECTRA 등 트랜스포머 비교(T5c)는 중간점검 이후로 미룬다.
- 목적: 규칙과 경량 모델이 서버에서 함께 도는 흐름을 보여주는 것. **성능 주장이 아니다.**
- 학습 데이터는 합성 중심(KR-MOB-SMISHING v1, CC BY-NC 4.0)이라 모델 파일을 저장소에 커밋하지 않는다.

## 구조

- `CompositeAnalyzer`(`backend/app/analyzers.py`)가 `RuleBasedAnalyzer`(규칙 + URL 평판)와 모델을 **둘 다 실행**하고 종합한다. 규칙에 걸려도 모델을 생략하지 않는다 (short-circuit 금지).
- 모델 경계는 `TextRiskModel.score(text) -> float`(`backend/app/model_adapter.py`)이다. 테스트는 가짜 모델을 쓴다.
- 모델 입력은 원문에서 URL 구간을 `<URL>`로 바꾼 문장이다(`prepare_model_text`). 학습과 추론이 같은 함수를 쓴다. URL 직접 입력에는 모델을 쓰지 않는다.
- 추론은 스레드에서 돌리고 제한 시간은 1초다(개발 제안). 전체 분석 제한(5초)보다 짧아 모델이 느려도 504가 아니라 규칙 결과로 응답한다. 시간 초과 시 스레드는 끝까지 돌지만 결과는 버린다.

## 모델 파일과 로드

- 서버 시작(`create_app`) 시 한 번 로드한다. 백엔드 환경 변수 `PTOS_MODEL_PATH`에 모델 폴더(manifest.json + model.joblib)를 준다. 없으면 모델 단계를 끈다.
- 로드 전 확인: 경로가 저장소 안이면 거부, manifest 형식(같은 폴더의 파일 이름, 0~1 임계값), 모델 파일 SHA-256이 manifest와 일치, manifest의 scikit-learn 버전이 서버와 같음.
- joblib(pickle)은 로드할 때 코드를 실행할 수 있다. SHA 확인은 파일 바뀜을 잡을 뿐 신뢰할 수 없는 파일을 막지 못하므로 **직접 학습한 파일만** 쓴다.
- 로드 실패는 서버를 멈추지 않는다. 로그에는 고정 코드(예: `MODEL_SHA256_MISMATCH`)만 남기고 경로·예외 문자열은 남기지 않는다.

## 임시 종합 정책

| 규칙 결과 | 모델 신호 있음 (점수 ≥ 임계값) | 모델 신호 없음 · 단계 실패 |
| --- | --- | --- |
| 정보 부족 | **의심** (`policy_reason: MODEL_SIGNAL_ONLY`) | 정보 부족 유지 |
| 의심 | 의심 유지 (`policy_reason` 유지) | 유지 |
| 위험 | 위험 유지 (`policy_reason` 유지) | 유지 |

- 모델 신호는 판정을 올릴 수만 있고 내리지 않는다. `normal`은 아래 “정상 반환” 조건을 모두 만족할 때만 반환한다(v2). `confidence`는 `null`이고 점수는 응답에 넣지 않는다.
- `MODEL_SIGNAL_ONLY`는 "규칙에 행동 요구 조합은 없고 모델 신호만 있다"는 뜻이다. 명의 주장처럼 단독으로 판정을 올리지 않는 약한 규칙 근거가 함께 있어도 같은 코드를 쓴다.
- 모델 신호는 원문 구절 근거가 아니므로 `evidence`·`risk_factors`에 넣지 않는다. 기존 `FactorCode`로는 표현할 수 없다.
- 설명: 신호가 있으면 아래 문장을 붙인다. 정보 부족에서 의심으로 올릴 때는 정보 부족 머리말을 이 문장으로 바꾸고, 약한 규칙 설명은 뒤에 남긴다.
  > 문장 전체가 사기 문자에서 자주 보이는 표현과 비슷해요. 어떤 부분 때문인지는 알 수 없고, 사기라고 확정한 것은 아니에요.
- 행동 안내는 새 문장을 만들지 않는다. 규칙 근거가 없으면 기존 기본 두 줄이다.
- 화면 문장에는 "경량 모델", "학습 자료" 같은 내부 용어를 쓰지 않는다.

## 정상 반환 (v2, 임시, 팀 확정 필요, 2026-11-17)

사용자가 `normal` 허용 조건을 위임해 정했다. 방향은 "신호가 없으면 정상, 조금 있으면 의심, 많이 있으면 위험, 판단 근거가 없으면 정보 부족"이다. API 응답 `analysis_version`은 `rules-model-dev-v5`로 올렸다. API 계약은 바뀌지 않았다(`normal`은 원래 계약에 있던 값이다).

정상은 다음을 **모두** 만족할 때만 반환한다(`policy_reason: NO_RISK_SIGNAL_FOUND`). 하나라도 어긋나면 정보 부족 그대로다.

| 조건 | 이유 |
| --- | --- |
| 규칙 결과가 정보 부족 | 의심·위험을 정상으로 내리는 경로를 만들지 않는다 |
| 입력이 문장 형태(`sentence_present`) | 단편 입력·URL 직접 입력은 판단 근거가 없다 |
| 규칙 근거가 없거나 대괄호 머리말(`impersonation-header-v1`)뿐 | 머리말만 있는 안내문은 평범한 정상 문자다. 긴급성·불이익, 명의 주장, 가족 호칭 근거가 하나라도 있으면 정상이 아니다 |
| 주소가 없거나, 있으면 평판 조회를 실제로 마침 | 확인하지 못한 주소가 있는 문자를 정상이라고 하지 않는다. 조회 결과 없음을 정상의 근거로 쓰는 것이 아니라, 확인하지 못한 주소가 정상 판정을 막는 것이다. **평판 조회가 꺼져 있으면(기본) 주소가 든 문자는 정상이 될 수 없다** |
| 모델이 실행됐고 점수가 정상 임계값 미만(`clear`) | 규칙에 걸리지 않았다는 것만으로는 정상이 아니다. 문장 전체 비교에서도 사기와 거리가 멀어야 한다 |

- 정상 임계값 기준(임시): dev 교차검증(OOF)에서 **사기 점수의 최솟값**. 그보다 낮은 점수만 정상 후보다. 곧 OOF에서 사기 행이 정상 후보가 되는 경우가 0건이다(모델 신호 임계값의 "정상 행 신호 0건"과 대칭). manifest에 `normal_threshold`, `normal_threshold_found`, `normal_threshold_rule`, `oof_normal_counts`로 기록한다. 그런 값이 없으면 그 모델로는 정상을 반환하지 않는다. 정상 임계값이 없는 옛 모델 파일도 그대로 읽히며 정상을 반환하지 않는다.
- 모델 점수의 세 구간: 임계값 이상 → 모델 신호(정보 부족 → 의심), 정상 임계값 미만 → 정상 후보, 그 사이 → 변화 없음(정보 부족 유지).
- 모델이 없거나(`PTOS_MODEL_PATH` 미설정) 로드 실패·시간 초과·오류이면 정상을 반환하지 않는다. 분석하지 못한 단계가 있기 때문이다.
- 화면 문장: 머리말 "특별한 위험 신호를 찾지 못했어요. 그렇다고 안전을 보증하는 것은 아니에요." 근거가 없으면 행동 안내는 "지금은 따로 조치하지 않아도 돼요. 다만 돈·인증번호·개인정보를 요구하는 연락이 이어지면 다시 확인해 보세요."와 공식 연락처 확인 안내다. 머리말 근거가 있으면 그 설명과 안내를 유지한다.
- 조건부 추가 검토(LLM)는 정상 판정에 관여하지 않는다. 정상이 된 입력에는 호출하지 않는다.
- **(dev, 부풀려진 수치, eval-v2.1-dev `2dc10e52…`, LGAI는 학습·임계값에 쓰지 않음)**

| 모델 | 정상 임계값 | 학습 행 OOF: 정상 → 정상 판정 | 학습 행 OOF: 사기 → 정상 판정 | LGAI 행(학습 안 함): 정상 → 정상 판정 | LGAI 행: 사기 → 정상 판정 |
| --- | --- | --- | --- | --- | --- |
| e5 임베딩 `e5-small-lr-v2` | 0.374 | 64/149 | 0/158 | 0/92 | 0/100 |
| TF-IDF `tfidf-lr-v3` | 0.488 | 105/149 | 0/158 | 1/92 | **1/100** |

- 읽는 법: 학습 행의 "사기 → 정상 0건"은 기준 자체가 그렇게 고른 값이라 낙관적이다. 의미 있는 값은 학습에 쓰지 않은 LGAI 행이다. TF-IDF 모델은 LGAI 사기 100건 중 24건의 점수가 정상 임계값 아래였고(다른 조건이 대부분 막아 1건만 정상 판정), e5 모델은 0건이었다. **정상 판정에는 e5 모델을 권한다.** LGAI 정상 문자는 대부분 문장 형태로 끝나지 않아 e5 모델에서도 정보 부족으로 남는다.
- 대안(채택하지 않음): 규칙 근거가 없으면 모델 없이 정상(사기 → 정상이 크게 늘어난다. dev에서 규칙이 놓친 사기 67건이 모두 정상 후보가 된다), 단편 입력도 정상 허용(학습에 쓰지 않은 출처에서 검증되지 않았다), 정상 임계값을 사기 점수 하위 5% 지점으로 완화(정상 판정은 늘지만 dev에서 사기 → 정상이 생긴다).
- 남은 것: 봉인 test에서 "사기 → 정상 판정" 건수를 확인한다(하네스 이진 리포트에 줄이 있다). 팀이 조건과 화면 문장을 확정한다.

## 모델 단계 표시 (계약 변경 없음)

| 상황 | `analysis_stages`의 `lightweight_model` | limitations 문장 |
| --- | --- | --- |
| 신호 있음 / 없음 | `completed` | 참고용 비교 안내 / 안전 보증 아님 |
| `PTOS_MODEL_PATH` 없음 | `not_connected` | 기능이 꺼져 있어 규칙 결과만 표시 |
| 로드 실패 (저장소 안 경로, SHA·버전 불일치 등) | `unavailable` | 준비하지 못해 규칙 결과만 표시 |
| 시간 초과 / 추론 오류 | `unavailable` | 제때 끝나지 않음 / 문제가 생김, 규칙 결과만 표시 |
| URL 직접 입력 | `not_applicable` | 주소만 입력해 비교하지 않음 |

로드 실패·시간 초과·오류의 구분은 limitations 문장으로만 한다. 기계가 읽는 상태는 모두 `unavailable`이다.

**알려진 한계 (중간점검 이후 B안 검토):** 모델이 함께 돌아도 응답의 `analysis_mode`는 계약상 `"rules"`로 남는다. 상태 구분도 위처럼 거칠다. B안은 `analysis_mode`에 `"rules+model"`, 단계 상태에 `timeout`·`load_failed`를 추가하는 계약 변경이며 OpenAPI·생성 타입·`client.ts`·프론트 테스트를 함께 바꿔야 한다.

## 학습과 임계값 (`backend/train_model.py`)

- 라벨(D1-a): 사기 = `suspicious` + `dangerous`, 정상 = `normal`. `insufficient_information` 라벨과 URL 입력 행은 학습에서 뺀다.
- 라벨 기준 선택(`--labels binary`, **임시, 팀 확정 필요, 기본 아님**): 이진 라벨만 있는 dev 행도 학습에 쓰려는 선택 사항이다. `expected_binary` 우선, 비어 있으면 4단계 라벨에서 만든다. 임계값 기준은 같고 "expected=normal 행" 자리에 정상(legit) 라벨 행이 들어간다. 이 기준으로 학습한 모델을 서버·평가에 쓸지는 팀이 정한다. 사용법은 [EVALUATION.md](EVALUATION.md).
- **split=dev 행만** 학습·임계값 결정에 쓴다. test 행은 CSV 형식 검사로 읽은 직후 버리고 건수만 기록한다.
- dev 안에서 `campaign_id` 기준 층화 그룹 교차검증(`StratifiedGroupKFold`, 기본 5 fold, 시드 고정)으로 out-of-fold(OOF) 점수를 낸다. 같은 campaign은 한 fold에만 들어간다.
- **임계값 기준(임시, 팀 확정 필요):** OOF 점수에서 expected=normal 행이 모델 신호로 표시되는 경우 0건을 지키면서 사기 재현율이 최대인 값, 곧 normal 최고 점수보다 큰 사기 점수 중 가장 낮은 값이다. 규칙이 이미 의심으로 판정한 normal 행도 신호를 내지 않아야 하므로, 판정이 올라가는지로 따지는 것보다 엄격하다. manifest에 `threshold_status: "provisional-dev-cv"`로 기록한다. 그런 값이 없으면 `threshold_found: false`이고 서버는 그 모델로 신호를 내지 않는다.
- 같은 OOF 점수로 임계값을 골랐으므로 OOF 지표도 낙관적이다. normal 표본이 적으면 임계값이 크게 흔들린다.
- 최종 모델은 dev 전체로 다시 학습한다. 그래서 하네스로 dev를 다시 평가하면 in-sample이며 비교에 쓰지 않는다. dev 비교는 `train-report.md`의 OOF 결과를 쓴다.
- manifest에는 모델 버전, 시드, 설정, fold 수, 평가 CSV SHA-256, 모델 파일 SHA-256, 코드 커밋·작업 트리 상태, 라이브러리 버전, 건수, 임계값 상태가 들어간다. 원문은 없다.

## 후보 비교 (`backend/compare_models.py`, T5c 준비)

- 기준선과 다른 scikit-learn 구성(문자·어절 n-gram, 로지스틱 회귀·나이브 베이즈)을 같은 dev 행·같은 fold로 비교하는 도구다. 모델 파일을 만들지 않고 서버 모델을 바꾸지 않는다.
- **모델 선택은 팀 결정이다(AGENTS.md 결정 필요 3).** 2026-11-16에는 기준선 구성을 임시로 유지했다(아래 "재학습 기준"). 트랜스포머는 고정 임베딩 후보 2개를 dev로 비교했고 서버 모델로 채택하지는 않았다.

## 임베딩 모델을 서버 모델로 쓰기 (2026-11-17, 선택 기능, 임시)

사용자가 `multilingual-e5-small` 임베딩 + 로지스틱 회귀를 서버 모델로 써도 된다고 정했다(2026-11-17). 기본 설치와 기본 동작은 그대로이고, 이 모델 폴더를 `PTOS_MODEL_PATH`로 줄 때만 쓰인다. **종합 정책은 바뀌지 않았다**(정보 부족 → 의심만, 점수 비노출, `confidence: null`). API 계약과 `analysis_version`도 그대로다.

- 구조: 모델 파일(`model.joblib`)에는 분류기(로지스틱 회귀)만 들어 있다. 인코더는 manifest의 `embedding`(로컬 폴더, 입력 앞 글자, 최대 토큰 수 256, 가중치 파일 이름과 SHA-256)을 보고 서버 시작 때 한 번 읽는다(`backend/app/embedding_encoder.py`). 학습과 추론이 같은 인코더 함수를 쓴다.
- 로드 전 확인(기존 확인에 더해): 인코더 폴더가 저장소 밖일 것, 가중치 파일의 SHA-256이 manifest와 같을 것, `torch`·`transformers`가 설치돼 있을 것. 어긋나면 `load_failed`(고정 코드 `ENCODER_SHA256_MISMATCH`, `ENCODER_FILE_MISSING`, `ENCODER_UNAVAILABLE` 등)이고 **규칙 결과와 근거는 그대로 나온다.**
- 네트워크: 인코더는 로컬 폴더에서만 읽는다(`local_files_only`). 서버는 모델을 내려받지 않는다. 실행할 때 `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`을 함께 두기를 권한다.
- 의존성: 선택 파일 `backend/requirements-embedding.txt`(`torch==2.15.0` CPU, `transformers==5.23.0`). 서버를 띄우는 가상환경에 사용자가 직접 설치한다. 저장소의 `.venv`에는 설치하지 않았다.

- **(dev, 부풀려진 수치)** 수치는 위 "고정 임베딩 후보 비교" 표의 `multilingual-e5-small` 줄과 같다(같은 CSV·시드·fold).

## 검증 방식의 한계와 출처 제외 검증 (2026-11-17)

- `train_model.py`·`compare_models.py`의 교차검증은 `campaign_id`로만 묶는다. 같은 출처의 비슷한 문장이 학습과 채점에 함께 들어가므로 OOF 수치는 처음 보는 유형의 성능보다 높게 나온다.
- 2026-11-17에 출처 한 묶음을 통째로 빼고 학습해 그 묶음을 채점하는 검증을 임시 스크립트로 해 보았다. 모델 단독으로는 처음 보는 출처의 사기를 15~35%만 잡았고, eval-v2.1 test 1회 실행에서도 `e5-small-lr-v4`는 사기 72건 중 12건에만 신호를 냈다(HANDOVER 9절 “eval-v2.1 test 1회 실행과 그 뒤의 재검증”).
- 임계값 기준(“OOF 정상 오탐 0건”)은 처음 보는 유형에서 모델 신호를 거의 내지 못한다. 완화 여부는 정하지 않았다(AGENTS.md 결정 필요 2).
- 미세조정(e5 전체 가중치 학습)을 같은 방식으로 한 구성만 실험했다. 소량 추가 구성에서는 TF-IDF보다 낮았지만 LGAI class 2 사기 600행을 더한 구성에서는 세 모델 중 가장 높았다(105/258, 같은 검증). 한 번 실행한 결과라 아직 채택하지 않았다. 서버 로더는 그대로 쓸 수 있다: 미세조정한 인코더를 저장소 밖 새 폴더에 두고 `train_model.py --embedding 이름=폴더`로 분류기를 학습하면 manifest가 그 폴더와 가중치 SHA-256을 가리킨다.
- 모델 후보는 앞으로 출처를 뺀 검증으로 비교한다. 이 검증 도구는 아직 저장소에 없다(임시 스크립트).

## 학습 전용 세트로 모델 다시 고르기 (2026-11-24, 임시, 팀 확정 필요)

사용자가 승인한 추천안대로 학습 방식을 바꿨다. **모델 선택은 팀 결정이다(AGENTS.md 결정 필요 3).** 아래 선택은 한 사람이 dev만 보고 정한 임시 선택이다.

- **학습 방식:** 저장소 밖 학습 전용 세트 `finetune-v2-train.csv`(14,641행, 사기 6,589, SHA-256 `b1349ed7…`)로 학습하고, 미세조정의 조기 종료는 `finetune-v2-val.csv`(1,633행)로 본다. 두 파일은 train-v5에서 만들었고 test 겹침 제거 봉인은 사용자가 실행했다(HANDOVER 9절). **eval dev는 학습에 쓰지 않고** 후보 비교와 임계값에만 쓴다. 기존 `train_model.py`(dev 학습)는 남겨 두었다.
- **임계값:** dev 문자 499행에서 `campaign_id` 그룹 5 fold(`StratifiedGroupKFold`, 시드 20261124)로 나눠, 각 fold 행에는 다른 fold에서 고른 임계값을 적용한다(cross-fitted). 기준은 전과 같다(신호: 정상 라벨 행 신호 0건을 지키며 사기 재현율 최대, 정상: 사기 점수 최솟값). 서버 모델 폴더의 임계값은 dev 전체 점수로 고른 값이다(`threshold_status: "provisional-dev-crossfit"`).
- **모델 입력:** 학습 자료가 전화번호·긴 숫자를 `[전화번호]`·`[숫자]`로 가려 두었으므로 추론도 같은 함수(`mask_numbers`)로 가린다. manifest의 `number_masking: true`일 때만 적용하고 기존 모델은 그대로다.

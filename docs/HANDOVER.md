## 1. 현황 요약

React와 FastAPI를 연결한 **규칙 기반 개발 버전**이다. 문자·URL 입력, 위험 표현 추출, 근거와 행동 안내, 스크린샷 OCR과 사용자 확인까지 동작한다.

- 피싱 분류용 경량 AI와 LLM은 **미구현**이다. OCR의 인식 모델과 제품의 피싱 판정은 별개이며, 현재 피싱 위험도는 규칙으로만 판단한다.
- Google Safe Browsing은 정규화, 해시 대조, 캐시를 **가짜 응답으로만** 검증했고 실제 조회는 연결하지 않았다.
- **실제 피싱 탐지 정확도 검증은 한 번도 없다.** 기존 테스트 통과는 코드 동작 검증이지 탐지 성능 검증이 아니다.
- 결과 계약은 4종(`normal`, `suspicious`, `dangerous`, `insufficient_information`)이지만 현재 `normal`은 반환하지 않는다. 그래서 정상 문자도 정보 부족으로 나온다.

| 영역 | 구현됨 | 남은 것 |
| --- | --- | --- |
| 화면·API | 문자 입력, 서버 요청, 결과 표시, 빈 입력·오류 처리 | Figma 적용, 고령자 사용성 검증 |
| 규칙 분석 | 명의 주장, 금전·민감정보 요구, 링크·앱 요구, 긴급성, 근거, 템플릿. T4 임시 보강(`rules-dev-v3`): 대괄호 머리말·가족 호칭(약한 명의), 반말·의문형 요청, “확인” 계열 링크 요구, 불이익·청구, 임박 기한, 규칙 A·B | 팀 정책 확정(T1), 검수된 평가셋 재측정, 답장 유도·혜택·비밀유지·콜백 신호 |
| URL | 직접 입력, 본문 추출, HTTP(S) 검증, IDNA, 구두점 처리, 중복 제거 | 실제 평판 조회 |
| 평판 어댑터 | Safe Browsing v5 URL 표현, SHA-256, 전체 해시 일치, 캐시, 개발 예산 | 이용 조건 확인, HTTP 전송기, 실제 API 검증 |
| OCR | Tesseract 5 한국어·영어, 이미지 검증, 수정·확인 후 분석 | 실제 기기 캡처 품질 평가 |
| 경량 AI | 없음 | 데이터, 학습, 평가, 서버 연결 |
| LLM | 없음 | 조건부 호출, 비용·전송 정책 |
| 운영 | 개발 실행, CI 설정 | PWA 설치, AWS 배포, 운영 보호 |

## 2. 일정 위험

설계서 일정은 W8에 경량 모델과 조건부 LLM, W9에 1차 릴리즈다. 현재 경량 모델과 LLM이 모두 없고 평가 수치가 없으므로, **중간발표에 보여줄 수치를 만드는 것**이 가장 급하다. 현재 주차는 팀이 확인해 아래 로드맵에 날짜를 넣는다.

## 4. 평가셋 스키마 (제안)

원천 데이터의 이진 라벨을 4단계로 자동 변환하지 않는다. 4단계 라벨은 검수 지침에 따라 직접 부여한다.

| 컬럼 | 설명 |
| --- | --- |
| `id` | 고유 번호 |
| `text`, `url` | 입력 문자와 직접 입력 URL (없으면 비움) |
| `expected_level` | `normal` / `suspicious` / `dangerous` / `insufficient_information` |
| `label_reason` | 판정 근거와 경계 사례 여부 |
| `source`, `is_synthetic` | 출처와 실제·합성 여부 |
| `campaign_id` | 같은 캠페인·변형 문장·동일 도메인을 묶어 분할하기 위한 값 |
| `split` | `dev` / `test` (최종 테스트셋은 정책·임계값 조정에 쓰지 않음) |
| `review_status` | 검수자 간 합의 상태 |

- 정상 문자는 금융 안내, 택배, 인증, 광고를 나누어 포함하고, 정보 부족 사례와 OCR 오류·근거 충돌 사례도 별도로 넣는다.
- 현재 `normal`이 반환되지 않으므로, 하네스는 `normal` 기대 사례의 결과를 별도로 표시한다.
- 원본 데이터셋은 저장소에 커밋하지 않는다. 공개 가능한 최소 샘플과 스키마만 둔다.
- 하네스 사용법, `text`/`url` 중 하나만 채우는 규칙, 저장 위치와 개인정보 가리기는 `docs/EVALUATION.md`를 본다.

## 5. 시간 예산 (제안, 측정 필요)

| 경로 | PRD 목표 | 현재 개발 제한 | 상태 |
| --- | --- | --- | --- |
| 텍스트 분석 | 일반 요청 5초 | 서버 5초, 브라우저 10초 | 측정 전 |
| OCR 포함 분석 | 10초 | OCR 엔진 15초, 브라우저 25초 | PRD 목표와 불일치. Tesseract를 실측하고 OCR 교체 또는 목표 조정 중 선택한다. |
| 조건부 LLM 경로 | 별도 측정 | 미정 | LLM 연결 시 서버·브라우저 제한을 재설계한다. |

- 측정은 요청 전송부터 결과 수신까지이며, 이미지 경로의 사용자 확인 시간은 제외한다. 환경·입력 길이·동시 요청 수를 고정하고 p50, p95, 시간 초과 비율을 보고한다.
- 측정은 Windows 개발 환경과 배포 환경(Linux)에서 각각 한다. Windows는 `--reload`·`--workers`를 쓸 수 없어 결과가 다를 수 있다.
- 경량 모델은 서버 시작 시 한 번 로드하고, CPU 추론 지연과 메모리를 먼저 잰다. 배포 사양에 맞지 않으면 기준선 모델이나 더 가벼운 모델로 간다 (결정 기준은 T5c에서 정한다).
- 합격선(p95 등)은 팀이 T1에서 정한다. 이 문서는 값을 제안하지 않는다.

## 6. 데이터와 이용 조건

- AI-Hub 71983(PRD 10.1에 적었던 데이터)은 **비상업용 합성 보안 로그**이고 문자 수신 이벤트 121개가 포함돼 있다. 공개분은 CC BY-NC 4.0이다. 문자 분류의 주 데이터로 바로 쓸 수 없고 본문 추출과 정답 재검수가 필요하다. `benign_lookalike`를 정상 문자로 단순 변환하지 않는다. 보조 시나리오로 두고 충분한 정상·피싱 문자를 더 확보한다. 개별 이용 조건과 해외 클라우드 업로드 허용 범위를 확인한다. **[준비]**
- 금융감독원 신고 기반이라고 적었던 IEEE DataPort 데이터는 링크 제목 기준 보이스피싱(통화) 데이터이고 역번역·SMOTE 증강이 포함돼 있다. 문자·메신저와 도메인이 다르므로 맥락 분석의 보조 자료로만 쓴다. 실제 구성은 확인이 필요하다.
- AI-Hub SNS 데이터는 정상 문자(택배, 은행 안내, 인증번호)와 성격이 달라 정상 대조군으로 한계가 있다.
- Tranco 같은 인기 목록에 포함된 것만으로 안전 라벨을 정하지 않는다. PhishTank 등 각 목록의 제공 상태와 이용 조건도 확인한다.
- Safe Browsing은 비상업용이다. 상업 운영으로 전환하려면 별도 조건과 제품 검토가 필요하다. 키가 있어도 현재는 `policy_pending`으로 조회하지 않는다. 계정 쿼터, 과금, 필수 표시, 이용 조건부터 확인한다. 전체 해시와 위협 유형이 일치할 때만 악성으로 보고, 접두사 일치·결과 없음·정상 도메인 목록만으로 악성이나 안전을 단정하지 않는다. 사용자 URL 직접 접속과 자동 리디렉션 추적은 범위 밖이다.
- 메신저 피싱 참고 저장소(ku-autoai/MessengerPhishingDetection)는 이용 허락을 확인하기 전에 코드와 데이터를 가져오지 않는다.
- KoBERT 공식 배포는 Apache 2.0이지만 학습 데이터 조건은 별개다.
- 캡스톤 범위는 비상업 개발·검증이다. 유료 Family Tier 등 상업화는 데이터·API 조건을 재검토한 뒤 정한다.

## 7. 규칙 정책의 한계

규칙은 PRD를 바탕으로 프로젝트에서 작성한 개발용 정책이며 검증된 분류 규칙이 아니다. NIST Phish Scale은 단서 설명의 참고 자료일 뿐 현재 자동 판정 임계값의 근거가 아니다. 우회 표현, 부정, 인용은 놓치거나 오탐할 수 있고 실제 사칭 여부를 검증하지 않는다. 신호 6개(`FactorCode`): 기관·지인 명의 주장, 금전 요구, 인증번호·개인정보 요구, 링크 접속 요구, 앱 설치·실행 요구, 긴급성·불이익 압박. T4에서 계약을 바꾸지 않고 `rule_id`로 세부 신호(머리말, 가족 호칭, 확인 계열 링크, 불이익, 임박 기한)를 나눴다.

**현재 판정 정책(임시, 팀 확정 필요, `rules-dev-v3`)**: 같은 문맥 안의 ① 명시적 명의 + 금전/민감정보/앱, ② 금전 + 민감정보/앱, ③ 긴급성·불이익 + 민감정보 + 링크, ④ (규칙 A) 명의(머리말 포함) + 불이익 + 링크 요구 + 임박 기한, ⑤ (규칙 B) 가족 호칭 + 금전 + 링크 요구 → 위험. 그 밖의 구체적 요구 → 의심, 나머지 → 정보 부족. `normal`은 반환하지 않고 `confidence`는 `null`이다. 머리말·가족 호칭은 단독으로 판정을 올리지 않는다. 임박 기한은 당일·금일·오늘·내일·익일 + 기한 표현, 자정까지, 24시간 이내, 1일 남음까지이며 2일 이상 남은 기한과 날짜만 적힌 기한은 해석하지 않는다. 답장 유도 신호는 미구현이다. 상세와 한계는 `docs/RULE_POLICY.md`를 본다.

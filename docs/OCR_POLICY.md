# 스크린샷 OCR 개발 정책

PRD FR-02와 개발설계서 4·6·8장의 이미지 → OCR → 확인·수정 → 분석을 구현한다. OCR 성공은 위험 분석 성공이 아니다. 누락된 문자·URL, O/0·l/1, 줄바꿈으로 끊어진 주소를 추측하거나 자동 복원하지 않는다.

## 방식 선택

| 방식 | Windows / Linux 클라우드 | 추가 설치 | 비용 / 전송 |
| --- | --- | --- | --- |
| Tesseract 5 + kor/eng (선택) | 둘 다 CPU 실행 가능 | OS 실행 파일, 언어 데이터, Pillow | 무료, 계정·GPU 불필요. 실행 중 OCR 공급자로 전송 없음 |
| 브라우저 WASM OCR | 양쪽 브라우저 가능 | WASM/언어 파일과 브라우저 메모리 관리 | 로컬 처리 가능하나 이번 Python 어댑터·서버 자원 제한과 다른 구성이 필요 |
| EasyOCR / PaddleOCR | Windows/Linux 패키지·CPU 환경별 검증 필요 | 더 큰 ML 런타임·모델 다운로드 | 로컬 무료 실행 가능하나 현재 증분의 설치 부담이 큼 |
| 외부 OCR 서비스 | HTTP 환경에 따름 | 공급자 계정/키·이용 조건 검토 | 이미지 외부 전송, 요금/보관 정책 결정이 필요하므로 미연결 |

Tesseract의 한국어·영어 인식은 화면 품질에 따라 틀릴 수 있다. 이 선택은 정확도 우위나 제품 인수 합격을 의미하지 않는다. Windows는 공식 설치 문서가 안내하는 UB Mannheim 배포판을 사용하고 Linux는 OS 패키지를 사용한다. 언어 데이터 설치만 공식 tessdata_fast의 고정 버전에서 HTTPS·SHA-256 검증으로 다운로드한다. 실행 중 다운로드나 외부 통신은 없다. 라이선스는 Tesseract/tessdata_fast의 Apache-2.0 및 각 배포물의 고지를 확인한다.

이미지는 **현재 FastAPI 서버로 업로드**한다. PC에서 앱을 실행하면 PC에서, 클라우드에서 실행하면 해당 클라우드 서버에서 처리한다. '클라우드 실행도 PC 밖으로 나가지 않는다'고 설명하지 않는다. 외부 OCR·유료 서비스를 연결하지 않으므로 지금 별도 계정/키/결제 결정은 필요 없다.

## 개발 제한 (PRD 확정값 아님)

- JPG/JPEG·PNG 한 장, 파일 바이트 최대 **10 MiB (10,485,760)**, 디코딩 전 크기 확인 및 최대 **20,000,000 화소**. 확장자·MIME만 신뢰하지 않고 서버에서 시그니처/실제 형식과 전체 디코딩을 검증한다. 애니메이션 PNG는 지원하지 않는다.
- OCR 서버 실행 제한 **15초**, 브라우저 요청 대기 **25초**, 서버 프로세스당 이미지 OCR 동시 실행 **1개**. 이 숫자는 개발 기본값이며 PRD의 OCR 포함 10초 목표나 확정 SLA가 아니다. 동시 요청은 429로 재시도 안내한다.
- 텍스트는 기존 10,000 코드포인트, 중복 제외 URL 후보 최대 10개. 초과 내용을 조용히 자르지 않는다. OCR 결과의 URL 후보 초과는 텍스트를 보존하고 수정 안내를 제공한다.
- EXIF 회전만 보정하고 메타데이터를 제거한 PNG를 메모리에서 만든다. 리사이즈·URL 조합·철자 보정·LLM 복원은 하지 않는다. 위험도 confidence는 기존처럼 null이다. OCR 품질 confidence도 측정하지 않은 값을 만들지 않는다.

## API와 확인 경계

- `POST /api/v1/ocr`: JPEG/PNG **바이너리 본문**. multipart 대신 크기 제한을 적용한 메모리 스트리밍을 사용하여 업로드 프레임워크의 디스크 스풀을 피한다. 원본 파일명은 전송하지 않는다. 200은 추출 문자·URL 후보·경고만 반환하며 Analyzer/평판 공급자를 호출하지 않는다.
- `POST /api/v1/ocr/review`: 수정 중인 텍스트에서 순수 URL 추출만 다시 수행한다. 주소를 열거나 위험 분석하지 않는다. 사용자는 전체 텍스트 안에서 URL도 수정한다. 편집 이후 후보 목록을 갱신하고 이전 확인을 해제한다.
- `POST /api/v1/analyses`: `input_type: ocr_text`, 확인한 `content`, **ocr_confirmed: true**가 필수. 서버는 확인 플래그를 검증하지만 사람이 실제로 읽었는지 증명하는 인증 기능은 아니다. 브라우저는 사용자가 원본과 비교했다는 체크와 분석 버튼 클릭 전에는 호출하지 않는다.
- 이미지 교체·입력 방식 변경·취소는 이전 OCR/후보 요청과 확인을 무효화한다. 이전 응답이 늦게 도착해 새 내용을 덮지 못하게 한다. 내용을 수정하면 이전 분석 결과도 지운다.
- 글자/URL을 확인할 수 없으면 체크하지 않고 선명한 사진으로 재업로드하거나 문자 직접 입력으로 전환한다. 서버 장애·빈 OCR·시간 초과를 위험도 결과로 숨기지 않는다.

## 개인정보와 정리

원본, EXIF 제거 이미지, OCR 원문은 요청 메모리에만 둔다. Tesseract는 stdin/stdout 파이프를 사용하고 이미지/텍스트 임시파일·장기 저장소·로그를 만들지 않는다. 성공·실패·시간 초과·취소에서 파이프/이미지 객체를 닫고 실행 중인 자식 프로세스를 종료·회수한다. 디스크 임시파일이 없어 잔여 파일용 TTL 작업도 필요 없다. OS 강제 종료·메모리 덤프/스왑까지 안전 삭제를 보증하지 않는다. 운영 프록시의 본문 로깅·캡처 정책은 배포 전에 따로 확인한다.

브라우저 미리보기는 Blob URL이며 교체/해제/페이지 이탈 때 revoke한다. 입력·이미지를 localStorage/IndexedDB/분석 이력에 저장하지 않는다. 현재 화면을 확인하는 동안만 브라우저 메모리에 유지한다. 오류 응답은 원문·파일명·OCR stderr를 노출하지 않고 no-store를 유지한다. 개발 테스트의 고정 합성 이미지는 사용자 업로드가 아니다.

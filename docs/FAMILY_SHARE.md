# 가족에게 보내기 (사용자 선택 공유) 설계

> **상태: 설계 초안 (2026-11-09). 구현하지 않았다.** 지금 화면의 `가족에게 공유 (준비 중)` 버튼은 안내 문구만 보여 주고 아무것도 보내지 않는다.
> 공통 규칙은 `AGENTS.md`, 작업 방식은 `DEVELOPMENT.md`를 따른다. 이 문서는 AGENTS.md를 바꾸지 않는다. AGENTS.md 수정은 이 문서가 확정된 뒤 따로 진행한다(7절).

## 0. 범위

**이번 범위**

- 사용자가 결과 요약을 **직접** 가족에게 보내는 기능. 결과 화면의 `가족에게 공유 (준비 중)` 버튼을 대체한다.
- 자주 보내는 가족(신뢰 연락처) 1~2명의 **표시 이름**을 사용자 기기 안에만 저장.

**이번 범위가 아닌 것** (11절 "향후 확장"에만 적는다)

- 가족 계정, 자동 위험 알림, 분석 기록, 서버 DB. AGENTS.md는 이 중 가족 계정·자동 알림·장기 분석 이력을 최종 MVP에서도 제외한다.

## 1. 원칙과 데이터 흐름

```
결과 화면(브라우저 메모리의 응답) ─▶ 요약 문장 만들기(프론트 고정 문구)
   ─▶ navigator.share({ text })  또는  navigator.clipboard.writeText(text)
   ─▶ 기기 공유 시트 / 사용자가 붙여 넣는 앱  ── 여기부터 우리 통제 밖
```

- **서버를 거치지 않는다.** 보내기 흐름에서 새 HTTP 요청이 0건이어야 한다. 백엔드 변경도 없다.
- 보내는 수단은 `navigator.share`의 `text`와 클립보드 복사뿐이다. `files`(이미지), `url` 필드는 쓰지 않는다. `sms:`·`kakaotalk:` 같은 앱 링크, 새 창, 외부 서비스로의 자동 이동도 쓰지 않는다.
- 보내는 것: 2절의 요약 문장 하나.
- **보내지 않는 것:** 문자 원문, 이미지, OCR 결과, 전체 URL(`urls[].original_url`·`normalized_url`·`ascii_host` 포함), 원문 조각인 `evidence[].snippet`과 좌표, `request_id`, `explanation`, `limitations`, `analysis_stages`, `analysis_version`, `policy_reason`.
- **우리 통제 밖:** 사용자가 공유 시트에서 고른 앱(카카오톡, 문자, 메일 등)이 그 문장을 어디로 어떻게 전송·보관·백업하는지는 PtoS가 알 수도, 제어할 수도 없다. 각 앱과 운영체제의 정책을 따른다. 클립보드에 복사한 문장도 다른 앱이나 클립보드 기록 기능이 읽을 수 있다. 이 사실은 보내기 전 확인 화면에 짧게 알린다(4절).
- 연락처 정보는 외부로 보내지 않는다. 신뢰 연락처의 표시 이름은 화면 문구에만 쓰고 공유 데이터에 넣지 않는다. 받는 사람은 사용자가 공유 시트에서 직접 고른다(D5).
- `navigator.share`는 보안 컨텍스트(HTTPS 또는 localhost)와 사용자 클릭이 필요하다. 데스크톱 브라우저 일부는 이 기능이 없어서 복사로 대체된다(4절).

## 2. 보내는 내용

### 2.1 구성 (프론트 고정 문구, D3)

1. 서명 한 줄: `[PtoS]` (D7)
2. 등급: 화면과 같은 이름(위험 / 의심 / 정보 부족 / 정상)을 **글자로** 쓴다. 색이나 기호에 의존하지 않는다.
3. 위험 요소 이름: 응답의 `risk_factors`를 그대로 쓴다. 이 값은 서버의 고정 라벨이고 원문 조각이 아니다(`backend/app/analyzers.py`에서 `evidence.label`로 만든다). 예: "금전 지급 요구", "인증번호·개인정보 요구".
4. 가족에게 부탁하는 행동: 등급별 고정 문장(2.2).
5. 고지 한 줄: "자동 분석이라 틀릴 수 있어요. 문자 원문은 넣지 않았어요."

### 2.2 등급별 원칙

| `risk_level` | 등급 문장 | 가족에게 부탁하는 행동 (예시, 확정 문구 아님) |
| --- | --- | --- |
| `dangerous` | 결과: 위험 | "저에게 전화해서 이 문자에 대해 같이 확인해 주세요." |
| `suspicious` | 결과: 의심 | "시간 될 때 저에게 전화해서 같이 확인해 주세요." |
| `insufficient_information` | 결과: 판단할 정보가 부족했어요 | "저에게 전화해서 어떤 문자인지 같이 봐 주세요." |
| `normal` | 지금 구현은 반환하지 않는다 | 생기더라도 "안전해요"라고 쓰지 않는다. "위험 요소를 찾지 못했지만 안전을 보장하지는 않아요" 수준으로 쓴다. |

- `insufficient_information`은 중간 위험도가 아니므로 "조금 위험" 같은 표현을 쓰지 않는다.
- 행동 문장은 **가족과 연락해 함께 확인하라**는 요청만 담는다. 문자 속 기관·사람에 대한 단정이나 기관 전체에 대한 일괄 단정은 쓰지 않는다. 판정 근거를 새로 만들지 않는다.
- 프론트의 고정 문구는 화면 표시용 문장이다. 분석 규칙(판정·조합)을 프론트에 넣지 않는다는 AGENTS.md 경계와 충돌하지 않는다. 문장은 `risk_level`과 `risk_factors`를 고르기만 하고 판정을 다시 계산하지 않는다.
- `risk_factors`가 비어 있으면(예: 규칙 근거 없이 다른 분석 신호로 `suspicious`가 된 경우) 위험 요소 줄을 빼고 "특정 표현을 짚지는 못했어요"로 대신한다. 화면에 내부 용어("경량 모델" 등)를 쓰지 않는다.
- `risk_factors`에 URL 평판 라벨("URL 위협 목록의 전체 해시 일치")이 있으면 AGENTS.md의 Google 표기 규칙에 따라 "Advisory provided by Google" 한 줄을 붙인다. 사용자 URL은 넣지 않는다. 고정 Advisory 링크를 문장에 넣을지는 구현 때 확인한다(9절 열린 질문).

### 2.3 길이 (D7)

- 목표는 "문자 1건 분량", 즉 받는 사람의 휴대폰 한 화면에 들어오는 길이다. 구현 기준은 **서명 포함 공백 포함 약 200자 이내**를 제안한다(개발 제안, 확정값 아님).
- 참고: 한국 이동통신의 단문(SMS, 90바이트, 한글 약 45자)에는 등급·요소·행동·고지가 다 들어가지 않는다. 문자 앱으로 보내면 장문(LMS)으로 바뀔 수 있다. 이것은 사용자의 문자 요금제와 앱에 달린 일이고 PtoS가 정하지 않는다.
- 위험 요소가 많아 길이를 넘으면 앞의 3개만 쓰고 "외 N개"로 줄인다(제안).

### 2.4 원문 포함 옵션 (D2: 포함하지 않음)

이번 범위에서는 원문, 원문 조각, URL을 어떤 옵션으로도 넣지 않는다. 화면에 "원문 포함" 스위치를 만들지 않는다.

## 3. 개인정보 가림 확인 화면 (참고: 나중에 원문 포함 옵션을 추가할 때)

D2에 따라 이번 범위에는 이 화면이 없다. 나중에 원문 포함을 검토할 때를 위해 요점만 남긴다.

- 자동 가림 후보: 전화번호, 계좌번호, 주민등록번호 형태, 인증번호 형태, 카드번호 형태. 이름·주소는 자동으로 찾기 어렵다.
- 동작: 가린 미리보기 → 사용자가 직접 고침 → "확인했어요" 체크 → 보내기 켜짐. 내용을 고치면 체크가 풀린다(OCR 확인 흐름과 같은 원칙).
- 한계: 정규식 가림은 완전하지 않다(띄어쓰기·특수문자를 끼운 번호, 한글로 쓴 숫자, 이름·주소, 이미지 속 글자를 놓친다). 그래서 사용자 확인 없이는 보낼 수 없게 해야 한다. 원문 안의 URL은 별도 정책이 필요하다.
- 도입하면 이 화면의 단위·e2e 테스트와 AGENTS.md 규칙 문구를 다시 검토한다.

## 4. 화면 흐름

```
결과 화면
  └─ [가족에게 보내기]
       └─ 보내기 확인 화면
            · 보낼 문장 미리보기 (읽기 전용, 일반 텍스트)
            · 신뢰 연락처가 있으면 "어머니에게 보내기"처럼 표시
            · 안내: "보낼 사람은 다음 화면에서 고르세요."
            · 안내: "보낸 뒤에는 고른 앱(카카오톡, 문자 등)의 방식대로 전송·보관돼요."
            · [보내기]  [취소]
               ├─ share 지원 ─▶ navigator.share({ text })
               │     ├─ 성공       ─▶ "공유 시트에 넘겼어요. 가족에게 보내졌는지 확인해 주세요." (D6)
               │     ├─ AbortError ─▶ 실패로 표시하지 않음. 확인 화면으로 돌아감
               │     └─ 그 밖의 오류 ─▶ 복사로 대체
               └─ share 미지원 / 오류 ─▶ navigator.clipboard.writeText(text)
                     ├─ 성공 ─▶ "복사했어요. 가족에게 보낼 앱에 붙여 넣으세요."
                     └─ 실패 ─▶ 문장을 선택 가능한 텍스트 상자로 보여 주고 직접 복사하도록 안내
```

- **성공 문구의 한계:** `navigator.share`가 성공해도 공유 시트가 앱에 넘겼다는 것까지만 알 수 있다. 실제로 가족에게 도착했는지는 알 수 없으므로 "보냈어요"라고 단정하지 않는다(D6).
- 키보드만으로 모든 단계를 쓸 수 있어야 한다. 확인 화면을 열면 제목에, 닫으면 [가족에게 보내기] 버튼으로 포커스를 돌린다. 결과 안내는 `role="status"`로 읽힌다.
- 큰 글씨·명확한 라벨 원칙을 지킨다. 문장 미리보기는 HTML로 해석하지 않는다.
- 보내기 확인 화면은 결과 화면의 일부다. 결과를 해제하는 동작(다시 확인하기, 입력 수정, 홈으로)을 하면 확인 화면과 만든 문장도 함께 버린다.
- 만든 문장은 컴포넌트 메모리에만 두고 어떤 저장소에도 쓰지 않는다.

## 5. 신뢰 연락처

### 5.1 저장하는 것과 위치

| 항목 | 결정 |
| --- | --- |
| 저장 데이터 | **표시 이름만**(예: "어머니", "큰딸"). 전화번호·카카오 ID·메일 주소는 저장하지 않는다(D4). |
| 개수 | 최대 2명 |
| 위치 | `localStorage` 키 하나(예: `ptos.trustedContacts`). 서버, 쿠키, IndexedDB, PWA 캐시에는 넣지 않는다. |
| 형식(제안) | `{"version": 1, "contacts": [{"id": "<무작위>", "name": "어머니"}]}`. 이름은 20자 이내, 공백만 있는 이름 거부. |
| 넣지 않는 것 | 분석 원문·결과·URL, 보낸 시각, 보낸 횟수, 보낸 기록 |

- 표시 이름은 화면 문구("어머니에게 보내기")에만 쓴다. 공유 문장과 공유 데이터에는 넣지 않는다.
- 저장값이 형식에 맞지 않거나 읽기·쓰기가 실패하면(사생활 보호 모드, 저장소 차단) 연락처 없이 동작하고 저장값을 지운다. 보내기 자체는 연락처 없이도 된다.
- 이 데이터는 이 브라우저에만 있고, 브라우저 데이터를 지우거나 다른 기기에서 열면 없다고 화면에 알린다.

### 5.2 흐름

- **등록:** 보내기 확인 화면 또는 별도 "자주 보내는 가족" 화면에서 [추가] → 이름 입력 → [저장]. 2명이 차면 [추가]를 숨기고 이유를 알린다.
- **수정:** 이름 옆 [고치기] → 입력 → [저장]. [취소]하면 바꾸지 않는다.
- **삭제:** [지우기] → "어머니를 목록에서 지울까요?" 확인 → 지움. 저장된 이름만 지워지고 다른 것에는 영향이 없다고 알린다.
- **전체 삭제:** 목록을 비우면 localStorage 키 자체를 지운다.

### 5.3 알려진 한계

- **번호를 저장하지 않아서 생기는 단계:** 신뢰 연락처를 등록해도 공유 시트에서 가족을 **매번 다시 골라야** 한다. 어르신에게는 단계가 하나 늘어나는 셈이다. 1차 구현은 개인정보 위험이 작은 이 방식(D4-A)으로 하고, 고령자 사용성 테스트에서 불편이 확인되면 끝 4자리만 저장하는 방식(C)이나 번호 저장(B)을 다시 검토한다. B는 저장 위험이 커서 7절의 규칙 문구와 테스트를 함께 바꿔야 한다.
- 표시 이름과 실제 받는 사람이 다를 수 있다(공유 시트에서 다른 사람을 골라도 막을 수 없다). 화면 문구는 "어머니에게 보내기"이지만 앱은 실제 수신자를 확인하지 못한다. 그래서 "보낼 사람은 다음 화면에서 고르세요"를 항상 보여 준다.
- 공유 시트의 앱 목록과 동작은 기기·브라우저·운영체제마다 다르다.

## 7. AGENTS.md 저장소 규칙과의 관계 (D1)

현재 AGENTS.md "반드시 유지할 동작"은 원문·이미지·결과·전체 URL을 localStorage·IndexedDB·PWA 캐시에 불필요하게 저장하지 않도록 한다. 신뢰 연락처 이름은 분석 데이터가 아니지만, e2e가 localStorage 전체가 비었는지를 확인하므로 규칙과 테스트를 명시적으로 맞춘다.

**D1 결정: A안. 기존 규칙은 그대로 두고 예외를 덧붙인다.** 이 문서가 확정된 뒤 AGENTS.md에 넣을 제안 문구:

> 사용자가 직접 등록한 신뢰 연락처(표시 이름만)는 localStorage 저장을 허용한다. 분석 원문·결과·URL·전체 URL은 여전히 금지한다.

- 지금은 AGENTS.md를 바꾸지 않는다.
- 나중에 글씨 크기·TTS 같은 사용자 설정을 함께 만들면, 규칙을 "분석 데이터"와 "사용자 설정 데이터"로 나누는 B안으로 다시 검토할 수 있다.
- AGENTS.md "미확정 사항"의 "사용자 선택 가족 공유는 별도 채택이 필요하다" 문장을 이 문서로 연결할지는 이 문서가 확정된 뒤 따로 정한다.

## 8. 테스트 계획

자동 테스트는 실제 공유 시트나 실제 앱으로 보내지 않는다. `navigator.share`와 `navigator.clipboard`는 가짜로 바꾸고, 넘어간 문장은 검사가 끝나면 버린다.

### 8.1 단위 (vitest)

- 등급별 문장 생성: 등급 글자, `risk_factors`, 고정 행동 문장, 서명, 고지가 들어간다.
- 문장에 원문, `evidence[].snippet`, `urls[]`의 모든 주소 필드, `request_id`, `explanation`이 **들어가지 않는다**(원문과 URL이 들어 있는 응답 고정값으로 확인).
- `risk_factors`가 빈 경우, URL 평판 라벨이 있는 경우(Google 표기), 길이 초과 시 줄이기.
- 공유 분기: share 성공 → D6 문구 / `AbortError` → 실패 표시 없음 / 그 밖의 오류 → 복사 / share 없음 → 복사 / 복사 실패 → 직접 복사 상자.
- 신뢰 연락처: 등록·수정·삭제·전체 삭제, 2명 한도, 이름 길이·공백 검증, 손상된 저장값과 저장소 예외 처리. 저장값에 이름 외 필드가 없다.
- 결과 해제(다시 확인하기, 입력 수정, 홈으로) 시 확인 화면과 만든 문장이 사라진다.
- 서버 요청: 보내기 흐름 동안 `fetch` 호출 횟수가 분석 요청 1회에서 늘지 않는다.

### 8.2 e2e (Playwright, 실제 FastAPI 연결)

- 분석 결과가 나온 뒤 요청 기록을 시작해, 보내기 흐름 전체(확인 화면 → 보내기 → 안내)에서 **네트워크 요청 0건**, 팝업 0건.
- 가짜 `navigator.share`가 받은 값에 `text`만 있고 `url`·`files`가 없다. `text`에 입력 원문과 URL 문자열이 없다.
- share가 없는 환경을 흉내 내 복사로 대체되는지 확인한다.
- **저장소 확인:** localStorage 키는 허용된 키(`ptos.trustedContacts`)만 있고, 그 값에는 표시 이름만 있으며, 입력 원문·결과 문장·URL 문자열이 없다. sessionStorage와 IndexedDB에 PtoS가 만든 항목이 없다. PWA 캐시가 있으면 응답·원문이 들어가지 않았다.
- 키보드만으로 보내기와 연락처 등록·삭제를 끝낼 수 있다.

### 8.3 기존 테스트를 바꾸는 계획

이 기능이 들어오면 아래 테스트는 지금 동작("준비 중", 아무것도 보내지 않음)을 확인하므로 새 동작에 맞게 바꾼다. **바꾸는 목적은 검사를 약하게 하는 것이 아니라 새 허용 범위를 정확히 못 박는 것이다.**

| 위치 | 지금 확인하는 것 | 바꿀 내용 |
| --- | --- | --- |
| `frontend/src/App.test.tsx`의 `가족에게 공유는 준비 중 안내만 보이고 요청을 보내지 않는다` | 준비 중 안내, fetch 1회 | 보내기 흐름 후에도 fetch 1회 유지 + 가짜 share가 받은 문장에 원문 없음 |
| `frontend/e2e/navigation.spec.ts`의 `결과 공유는 준비 중 안내만 표시하고 원문을 전달하지 않는다` | 준비 중 안내, 다시 확인하기 후 원문 유지 | 보내기 확인 화면 → 취소 → 다시 확인하기 후 원문 유지 |
| `frontend/e2e/navigation.spec.ts`의 `가족에게 공유(준비 중)를 눌러도 네트워크 요청·새 창·클립보드 쓰기가 없다` | 요청·팝업·share·클립보드 0건 | 요청·팝업 0건은 그대로. share/클립보드는 "사용자가 [보내기]를 누른 뒤 1회, 원문·URL 없는 문장만"으로 바꾼다. [보내기] 전에는 0건임을 함께 확인한다. |
| `frontend/e2e/analysis.spec.ts`의 `Object.keys(localStorage)` 빈 배열 단언 | localStorage가 비어 있음 | 연락처를 등록하지 않은 이 시나리오에서는 **빈 배열 그대로 유지**. 연락처를 등록하는 새 시나리오에서는 "허용된 키만 있고, 값에 원문·결과·URL 문자열이 없다"로 단언한다. |

"준비 중"을 확인하는 테스트는 위 표의 앞 세 개다(App 단위 1개, navigation e2e 2개). `frontend/e2e/result-design.spec.ts`는 버튼 이름 `가족에게 공유`가 보이는지만 확인하므로, 새 버튼 이름이 이 글자를 포함하면 바꾸지 않아도 된다.

### 8.4 수동 확인 (자동 테스트와 구분해 보고)

- Android(카카오톡, 기본 문자 앱), iOS(메시지, 카카오톡), 데스크톱 Chrome/Edge(share 지원 여부), Firefox(share 미지원 → 복사)에서 문장이 깨지지 않고 줄바꿈이 유지되는지.

## 11. 향후 확장 (Family Tier)

**검토 후보이지 계획이 아니다.** 가족 계정, 자동 위험 알림, 분석 기록, 서버 DB는 이번 범위가 아니다. AGENTS.md는 가족 계정·자동 알림·장기 분석 이력을 최종 MVP에서도 제외하고 있다.

도입을 검토하려면 먼저 정해야 할 것:

- **동의:** 누가(사용자 본인, 가족) 무엇에 동의하는지, 철회 방법.
- **보관 기간:** 서버에 무엇을 얼마나 두고 언제 지우는지.
- **전송 정책:** 무엇을 누구에게 어떤 경로로 보내는지, 원문·URL 포함 여부와 마스킹.
- **비용:** 알림 발송·서버 운영 비용과 상한.

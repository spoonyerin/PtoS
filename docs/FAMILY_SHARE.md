## 2. 무엇을 보내고 저장하나

| 항목 | 보내거나 저장함 | 보내지도 저장하지도 않음 |
| --- | --- | --- |
| 확인 요청 | 위험 단계(`risk_level`), 위험 요소 코드(`FactorCode`), 시각, 자동 알림 여부 | 입력 원문, 사진, 근거 구절, 사용자 URL, 보낸 번호, 분석 요청 id, 설명 문장 |
| 가족 연결 | 서로 부르는 이름(20자), 관계 | 전화번호, 연락처 목록, 계정 |
| 의견 | 고정 선택지 또는 직접 입력 100자 | — |
| 기기 | 서버가 만든 무작위 열쇠의 SHA-256, 시연용 가입 여부, 자동 알림 대상 | — |
| 웹 푸시 | 브라우저가 준 구독 주소·키(기기당 최대 3개) | 알림 본문의 이름·결과(고정 문장만 보냄) |

- 확인 요청과 의견은 **7일**(임시, `PTOS_FAMILY_RETENTION_DAYS`, 1~30) 뒤 지워요. 수락하지 않은 초대는 24시간 뒤 지워요.
- 브라우저에는 **기기 열쇠 하나만** localStorage(`ptos.familyDevice`)에 저장해요. 이름·결과·요청은 저장하지 않아요.
- "이 기기 정보 지우기"(가족 보호 → 시연용 설정)는 서버의 기기·연결·요청·구독과 브라우저 열쇠를 함께 지워요.
- 서비스 워커(`public/sw.js`)는 알림만 처리하고 fetch를 다루지 않아요. 요청·결과를 캐시하지 않아요.
- 알림 본문은 "가족이 문자 확인을 요청했어요" 같은 고정 문장이에요. 결과는 앱을 열어야 보여요. 웹 푸시는 브라우저 회사(Google·Apple·Mozilla)의 푸시 서버를 거치고, 본문은 표준 방식으로 암호화돼요.

## 3. 켜는 조건 (백엔드 환경 변수)

| 변수 | 값 | 없으면 |
| --- | --- | --- |
| `PTOS_FAMILY_DB_PATH` | 저장소 밖 SQLite 경로. `:memory:`는 서버를 끄면 사라지는 임시 저장(자동 테스트용) | 가족 API 503 `FAMILY_OFF`, `health/ready`의 `family: off` |
| `PTOS_PUSH_MODE` | `live-webpush` (정확히 일치) | 푸시 꺼짐(`push: off`). 화면은 기록에서 확인하라고 안내 |
| `PTOS_VAPID_PUBLIC_KEY`, `PTOS_VAPID_PRIVATE_KEY` | `backend/generate_vapid_keys.py` 출력 | 푸시 꺼짐 |
| `PTOS_VAPID_SUBJECT` | `mailto:` 또는 `https://` 연락처 | 푸시 꺼짐 |

저장소 안 경로는 거부해요(`db_in_repo`). 로그에는 고정 코드(`FAMILY state=…`, `FAMILY_PUSH result=failed`)만 남겨요.

## 4. API 계약 (2026-11-25 추가, 발표 시연 한정)

원본은 `backend/app/contracts.py`, 경로는 `backend/app/family_api.py`. 기기는 `Authorization: Bearer <기기 열쇠>`로 구분해요.

| 메서드·경로 | 설명 |
| --- | --- |
| `POST /api/v1/family/devices` | 기기 열쇠 발급 (201) |
| `DELETE /api/v1/family/devices/me` | 이 기기와 연결·요청·구독 삭제 (204) |
| `GET /api/v1/family/me` | 가입 여부, 연결 목록, 자동 알림, 푸시 구독 여부, 새 요청·의견 수 |
| `PUT /api/v1/family/premium` | 시연용 가입 켜기·끄기 |
| `POST /api/v1/family/invites` | 초대 만들기 (프리미엄 필요) |
| `POST /api/v1/family/invites/preview`, `/accept` | 초대 확인, 수락. 열쇠는 본문으로만 받아요(주소 로그에 남지 않게) |
| `DELETE /api/v1/family/links/{id}` | 연결 끊기 (양쪽 모두 가능) |
| `PUT /api/v1/family/auto-alert` | 자동 알림 대상 설정·해제 |
| `POST /api/v1/family/requests` | 확인 요청 보내기. `auto: true`는 동의한 대상과 같을 때만 |
| `GET /api/v1/family/requests?box=sent\|received`, `GET …/requests/{id}` | 기록, 상세(받은 사람이 열면 '확인함', 보낸 사람이 열면 '의견 읽음') |
| `POST /api/v1/family/requests/{id}/reply` | 의견 보내기 (받은 사람만, 한 번) |
| `GET /api/v1/family/push/key`, `PUT /api/v1/family/push`, `POST /api/v1/family/push/remove` | 푸시 공개 키, 구독, 해제 |

`ReadyResponse`에 `family`, `push`(`live | off`)를 추가했어요. 오류 코드는 `family_api.py`의 `FAMILY_ERRORS`에 있어요.
남용 방지 한도(개발 제안): 기기당 연결 5개, 하루 확인 요청 50건, 전체 기기 2,000개, 기기 등록은 서버 전체에서 10분에 30개.
연결·초대·알림 구독이 하나도 없이 24시간이 지난 기기는 지워요(한도를 채워 시연을 막지 못하게).

웹 푸시 알림 주소는 브라우저 푸시 서비스 호스트만 받아요: `fcm.googleapis.com`, `updates.push.services.mozilla.com`,
`web.push.apple.com`, `*.push.apple.com`, `*.notify.windows.com` (https, 443 포트, 사용자 정보 없음). 그 밖의 주소는
422 `INVALID_PUSH`로 거부하고, 보낼 때 한 번 더 확인해요. 서버는 리디렉션을 따라가지 않고 환경 프록시를 쓰지 않아요.
서버가 사용자가 준 주소로 요청을 보내는 구조라서, 서버 안쪽 주소로 요청을 보내게 만드는 공격(SSRF)을 막기 위해서예요.

## 5. 한계와 남은 위험

- **로그인 없음.** 초대 링크를 가진 사람은 누구나 수락할 수 있어요(24시간, 1회용으로 줄임). 기기 열쇠를 잃으면(브라우저 데이터 삭제) 연결을 다시 만들어야 해요.
- **결제 없음.** "프리미엄"은 서버의 표시 하나예요. 상용화하면 결제, Web Risk API 전환, 이용 약관이 필요해요.
- **웹 푸시는 기기·설정에 따라 늦거나 오지 않을 수 있어요.** iPhone은 홈 화면에 설치한 앱에서만 받아요. 실제 휴대폰 확인은 아직 하지 않았어요.
- 보호자의 "문제 없어 보여요"는 가족 의견이에요. 화면에 "PtoS 분석 결과가 아니고 안전을 보장하지 않아요"를 함께 보여요.
- Figma와 다른 점: 원문 요약·발신자 번호(보내지 않음), 연락처에서 고르기·전화번호 입력(받지 않음), 긴급 연락·공식 확인 가이드(이번 범위 밖), 실제 결제 금액(시연용 표시).
- 무료 사용자의 결과 화면은 Figma의 잠긴 "가족에게 공유" 대신 기존 공유 앱·복사 기능을 유지했어요.

## 6. 설계 초안(`docs/family-share-design` 브랜치, 2026-11-09)과 다른 점

- 초안 D1(신뢰 연락처 표시 이름만 localStorage)은 쓰지 않고, **기기 열쇠 하나만** localStorage에 둬요. 이름은 서버에 둬요.
- 초안 11절 "Family Tier"(가족 계정·자동 알림·기록·서버 DB)는 초안에서 범위 밖이었지만, 이번에 **발표 시연 한정**으로 만들었어요. 동의(자동 알림 동의 화면), 보관 기간(7일), 전송 정책(코드만, 고정 알림 문장), 비용(무료 서버·웹 푸시) 결정은 이 문서의 임시값이에요.
- 초안 D6("공유 시트에 넘겼어요…")는 기존 공유 앱 방식에 그대로 유지해요. 앱 안 전송은 서버가 기록한 확인·의견만 상태로 보여 줘요.
